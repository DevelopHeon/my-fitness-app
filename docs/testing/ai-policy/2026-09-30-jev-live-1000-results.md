# JEV 실호출 1,000건 평가

> 아래 판정은 실호출 당시 정책의 원본 기록이다. 판정 순서 수정 후 같은 응답으로 계산한 결과는 [후속 replay 보고서](2026-09-30-policy-rule-replay.md)에 분리해 기록했다.

2026-09-30에 변경 전 평가에 쓴 **동일한** `synthetic-baseline-1000-v1.jsonl`을 대상으로 JEV를 한 차례 호출했다. 이 문서는 입력 정책 gate의 결과이며, 실제 사용자에게 노출된 답변의 안전성 평가가 아니다.

## 실행과 재현 정보

- 실행: `aiPolicyEval`, `mode=jev-live`, `runs=1`, `allowDraft=true`, 직렬 호출·재시도 0회. 측정 요청 1,000건과 별도 워밍업 10건을 수행했다. 전체 1,000건 평가를 다시 실행하지 않았다.
- 데이터: 50개 의미 family × 20개 표현 변형, 라벨 상태 `draft-synthetic`; SHA-256 `e0bce629e9ddd2d7a2c033bd911443cf0dc8000d238f023b259b487c3a913286`. 독립적인 사람 검토나 holdout이 없다.
- 요청·응답 모델: `jev-1.13.0`; 정책 `fitness-policy-v1`; 질문 hash `97f72cee2b22878f6696ae3987b15d627e2ee949f85c2beace135abc154e4f51`; 기준 코드 commit `55128edabeeb410bf679535ea036ca28392796f6`.
- 임계값: 위험 검토 0.35, 행동 제한 0.70, 주제 확신도 0.60. 외부 호출 제한 시간 1,500ms.
- 원본: [manifest](jev-live-1000-v1/manifest.json), [전체 지표](jev-live-1000-v1/metrics.json), [케이스별 응답·판정](jev-live-1000-v1/cases.jsonl), [집계](jev-live-1000-v1/aggregate.json). 변경 전 [manifest](baseline-1000-v1/manifest.json), [지표](baseline-1000-v1/metrics.json), [케이스](baseline-1000-v1/cases.jsonl)는 수정하지 않았다. API 키는 산출물에 포함하지 않았다.

실행 명령은 다음과 같다. 프로젝트 `.env`의 `TYPESAFE_API_KEY`만 안전하게 읽어 Gradle 자식 프로세스 환경에 전달했다. `.env`는 Git 무시 대상이며 키 값은 출력하지 않았다.

```bash
./gradlew aiPolicyEval \
  -PaiPolicyEval.mode=jev-live \
  -PaiPolicyEval.dataset=src/test/resources/ai-policy/synthetic-baseline-1000-v1.jsonl \
  -PaiPolicyEval.allowDraft=true -PaiPolicyEval.runs=1 --no-daemon
```

## 평가 실패와 비용의 경계

17건의 오류 코드는 모두 `INVALID_RESPONSE`다. 평가 도구가 거부된 원본 응답이나 세부 검증 실패 위치를 저장하지 않아 원인(스키마, 확률, 사용량 필드 등)을 특정할 수 없다. 이 17건은 운영 계약상 답변 생성 없이 `AI_POLICY_UNAVAILABLE / 503`으로 처리되어야 하지만, **이 실호출은 정책 gate만 시험**했으므로 앱의 503·생성기 미호출은 별도 동작 테스트의 검증 범위다. 일부 실패 케이스의 추가 진단 요청에서 정상 응답을 받았어도 이번 1,000건 결과를 대체하지 않았다.

유효 응답 983건의 알려진 입력 사용량은 933,088 token이다. [TypeSafe가 공개한](https://typesafe.ai/blog/introducing-system-one-models-and-jev) 입력 100만 token당 $0.042를 가정한 **알려진 부분의 추정액**은 약 $0.03919다. 워밍업 10건의 추정액은 약 $0.00040이다. 실패한 17건의 사용량·청구 여부와 계정별 실제 단가는 확인하지 못해 전체 청구액은 산출하지 않았다. 원본 지표의 `policyCostUsd=null`은 이 이유 때문이다.

합성 데이터는 의미상 50개 family에 집중돼 있어 1,000개의 독립적인 실사용 질문으로 볼 수 없다. 사람 검토 gold, 실제 답변 E2E 안전성, 생성 비용, 전체 HTTP 왕복 지연, 운영 가용성은 미검증이다. 따라서 이 수치는 탐색적 입력 gate 측정이며 운영 품질 확정이나 자동 승격 근거가 아니다. 다음에 장애 원인을 좁히려면 민감한 원문을 남기지 않는 구조화된 파싱 실패 위치를 기록한 뒤 별도 실험으로 확인해야 한다.
