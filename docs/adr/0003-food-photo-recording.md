# ADR 0003 · 음식 사진 분석과 사용자 확인 후 기록

- 상태: Accepted
- 정리일: 2026-10-07. 2026-10-01 스펙과 현재 사용자 흐름을 근거로 작성한 회고 기록이다.

## 배경과 대안

음식 카탈로그를 먼저 등록하고 선택하는 흐름 대신 음식명과 섭취 칼로리를 바로 기록하려 했다.
사진에 여러 음식이 있는 경우 대화 결과마다 버튼을 눌러 하나씩 등록하는 흐름도 입력 부담이 컸다.
JEV 텍스트 정책 평가를 사진에도 적용하는 방법, OpenAI 이미지 분석, 분석 후 자동 저장을 검토했다.
이미지 판별·음식 후보·칼로리 추정은 텍스트 정책과 계약이 달랐고 추정값은 사용자 확인이 필요했다.

## 결정

사진은 고정된 이미지 요청과 Structured Outputs로 OpenAI를 한 번 호출한다.
JEV 텍스트 gate와 Ollama fallback을 사진 흐름에 연결하지 않는다.
식단 화면에서 음식 후보를 여러 입력 행의 초안으로 채우고 사용자가 수정·제외한 뒤 한 번 저장한다.
날짜·식사 구분은 시간 기준 기본값을 제공하고 사용자가 결정한다. 원본 사진은 앱 DB·로그에 보관하지 않는다.
정확한 입력·판별·실패 계약은 [AI](../ai.md#음식-사진-분석), 화면 규칙은 [Product](../product.md#식단-기록)를 따른다.

## 결과와 비용

카탈로그 관리와 음식별 등록 동작을 줄일 수 있다. 분석만으로 기록이 생성되지는 않는다.
일반적인 1인분 추정은 실제 섭취량이나 공식 영양정보가 아니며 사용자가 수정할 수 있어야 한다.
기존 카탈로그 schema를 제거한 V11 이후에는 이전 이미지 rollback만으로 DB 호환을 복구할 수 없다.
이미지 계약·실패 동작 검사와 실제 음식 인식·열량 정확도·모바일 실사용은 별도 검증이다.
