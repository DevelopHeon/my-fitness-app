# Spec 문서 작성 규칙

이 디렉터리는 구현 단위별 스펙을 기록한다.

## 파일명

```text
YYYY-MM-DD-요일-pr-NNN-주제.md
```

예시:

```text
2026-09-18-fri-pr-001-project-bootstrap.md
2026-09-18-fri-pr-002-workout-foundation.md
```

## 작성 기준

- 날짜와 요일을 반드시 기록한다.
- 하나의 구현 PR이 해결해야 하는 범위를 하나의 문서로 작성한다.
- 구현 목적, 포함/제외 범위, 완료 조건을 중심으로 작성한다.
- API나 데이터 구조는 구현 판단에 필요한 수준까지만 기술한다.
- PR 번호가 확정되기 전에는 예정 번호를 사용하고, 실제 PR 생성 시 맞춘다.
- 구현이 끝나면 결과와 후속 과제를 문서 하단에 갱신한다.

## 공통 섹션

1. 배경 및 목적
2. 구현 범위
3. 비기능 요구사항
4. 데이터/API 영향
5. 완료 조건
6. 제외 범위
7. 구현 결과 및 후속 과제

장기 제품 요구사항은 [PRODUCT_SPEC.md](./PRODUCT_SPEC.md)를 기준으로 한다.
